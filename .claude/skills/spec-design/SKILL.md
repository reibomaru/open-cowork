# cowork仕様設計フレームワーク

## 大前提

coworkはLLMハーネス型の汎用エージェントである。

- **ユーザージャーニー** = What（ユーザーが達成したいこと）
- **Skill / Tool** = How（ジャーニーを実現する手段）
- **仕様書** = ジャーニーとSkill/Toolのマッピング

仕様書とは「ユーザーがどんな要望を出し、それをどのSkill/Toolの組み合わせで実現するか」を定義する文書である。

## Skill と Tool の区別

| 区分 | 定義 | 例 |
|------|------|-----|
| **Skill** | 判断・ワークフロー・プロンプト知識を含む高レベル操作。複数Toolを組み合わせる | 「PR作成」「仕様書設計」 |
| **Tool** | 外部システムへの単一操作。副作用は1つ | 「ファイル読み書き」「API呼び出し」 |

## 設計手順

1. ユーザージャーニーを列挙する（技術からの逆算禁止）
2. 各ジャーニーに必要なSkill群を特定する
3. 各Skillが必要とするTool群を特定する
4. 複数ジャーニーで共通するSkill/Toolを抽出する
5. 存在しないSkill/Toolを「要実装」として明示する
6. マッピング表で対応関係を整理する

## 仕様書の構成

仕様書は以下のセクション構成で記述する。
詳細テンプレートは [references/spec-template.md](references/spec-template.md) を参照。

1. **概要** - 目的と対象ユーザー
2. **ユーザージャーニー** - ペルソナ、要望例、期待動作、利用Skill
3. **Skill定義** - トリガー、ワークフロー、利用Tool、入出力
4. **Tool定義** - インターフェース、依存外部システム
5. **マッピング表** - ジャーニー × Skill × Tool の対応関係
